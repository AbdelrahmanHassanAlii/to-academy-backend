# Implemented database schema — through Phase 2.3

The Phase 0 architecture remains the historical plan. This document records implemented relationships; authoritative field constraints are in models and OpenAPI. All models use the existing Mongoose connection. No new database or migration framework is introduced.

| Collection | Relationship and lifecycle                                                                                                                                                                                                                                                                                                       | Indexes                                                                                                    |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| admins     | Safe profile identity; active state/role reloaded for every protected request. Password hash excluded by default.                                                                                                                                                                                                                | Unique normalized email                                                                                    |
| categories | Localized name/description, optional image ObjectId, isActive/sortOrder/timestamps. DELETE soft-deactivates, retaining course references.                                                                                                                                                                                        | Unique slug; active+sortOrder+id; sortOrder+id                                                             |
| courses    | Required category ObjectId -> categories; nullable thumbnail ObjectId reserved for Media. Localized title/summary/description/SEO, curriculum, lectureCount, duration, targetAudience, trainingMode, price/currency/isFree, draft/published/archived, featured, first publishedAt, timestamps. Archive preserves ids/references. | Unique slug; status+createdAt+id; category+status+createdAt+id; status+featured+createdAt+id; createdAt+id |
| sessions   | Existing connect-mongo records; administrator id and timing/CSRF state, no credential hashes.                                                                                                                                                                                                                                    | Store-managed expires TTL                                                                                  |

Course indexes use descending date/id. Course updates use optimistic versioning; archive increments the version. first publishedAt is server-owned, retained after unpublishing and used to lock published slugs. API serializers hide __v and _id.

Prices use nullable integer piastres: null unannounced, free zero, non-free positive. Category existence is checked by service before writes; active state additionally required for resulting published state. Public reads require an existing active category. Supported APIs never hard-delete a category/course. There are no native foreign-key constraints, transactions or duplicated category labels inside course documents. Concurrent category changes are bounded by live public-read filtering, per the single-admin MVP architecture.

Thumbnail/image references are syntax-checked only until Media exists; they are not image URLs or embedded data. No Courses seed or data migration. Existing installed databases receive explicitly declared indexes at startup; no syncIndexes, index deletion or destructive data rewrite. Index creation failures stop startup and require investigation.

Full contracts: [Courses](courses.md), [Categories](categories.md), [authentication](authentication.md), [OpenAPI](openapi.yaml). Lectures, registrations and other planned collections are not implemented in this phase.
